# Working in this repo

Onboarding material that gets 2026 NIAID AI Codeathon participants calling Argo,
Argonne's LLM gateway. The audience is a scientist with a laptop and a deadline, not
an Argo administrator.

## The one rule that matters: three copies stay in sync

Every code snippet exists in three places. Change one, change all three:

| | |
|---|---|
| `README.md` | The GitHub landing page. Canonical prose. |
| `argo-quickstart.html` | Standalone styled page, handed out as a file. Mirrors the README section for section. |
| `examples/` | The runnable copy. What participants actually execute. |

`examples/README.md` is the per-file index and repeats a few parameter claims — check
it too when parameter rules change.

`argo-quickstart.html` has two things that will bite you:

- **Section numbers are hardcoded** as `<span class="n">NN</span>`. Renumbering a
  section means editing every later one by hand.
- **The table of contents is generated by JS** from `main section`, so it follows
  along automatically — but only if each section keeps its `id` and its `<h2>`.

It also has a username box that rewrites every `.u` span and persists to
localStorage, plus a "Forget" button that clears it. Adding a new spot where a
username appears means giving it `class="u"`.

## Do not "clean up" these parameters

Each one is load-bearing and was established by measuring the gateway, not by reading
docs. Removing any of them reintroduces a traceback a participant already hit:

- **`temperature=1`, stated explicitly** — never omit it. `claudesonnet5` and the
  `gpt5`/`gpt55`/`gpt56*` models reject every other value, and LangChain and
  LlamaIndex inject their own defaults (LlamaIndex's `OpenAILike` uses `0.1`) when the
  argument is absent. Omitting it is not the same as not sending it.
- **`extra_body={"max_tokens": N}`** in `langchain-openai` — recent versions put
  `max_completion_tokens` on the wire, which Argo ignores for Claude models.
- **`check_embedding_ctx_length=False`** on `OpenAIEmbeddings` — otherwise LangChain
  pre-tokenizes and posts token-ID arrays, which Argo rejects with a 422. Argo's
  embeddings endpoint takes strings only.
- **Filtering content blocks by `type == "text"`** in the Anthropic examples —
  `claudeopus5` has extended thinking on by default, so `content[0]` is a
  `ThinkingBlock` with no `.text`.
- **`max_tokens` ≥ 2048 for `gemini35flash`** — it spends its budget on internal
  reasoning and returns an empty candidate at small values.
- **`max_tokens` ≤ 21000 when streaming Anthropic models** on `/v1/chat/completions`,
  or the gateway 500s.

§6 of the README is the full measured matrix. It is dated; treat it as a snapshot.

## Model IDs are Argo's, not the vendor's

`claudeopus5`, not `claude-opus-5`. `gpt56sol`, not any upstream name. There is no
pattern worth guessing — `GET /v1/models` is the only source of truth, and Argo adds
models often. If a model ID in the docs looks stale, check the live list before
changing it.

## Verify before you write it down

Do not infer Argo's behavior from the vendor's documentation or from a sibling model.
The gateway does its own parameter handling and the two diverge. Several confident
claims written by analogy turned out wrong and surfaced as tracebacks in a
participant's terminal.

If something genuinely cannot be checked — client library internals, package
availability — say so and label that claim unverified rather than letting it sit
alongside measured ones.

**Known unverified:** everything in `examples/agents/` (Claude Code, Continue, aider)
is written from convention and has never been run end to end. The Python files in
`examples/open/` are also unexecuted — no `openai` package is installable on the host
they were written on — though every behavior they claim was checked against the live
servers with raw HTTP, and the shell examples there were run.

## Section 2 is coordinator-approved language

"What you may send" states Argonne's CUI and data-residency position. The wording was
supplied by the codeathon coordinators and reviewed. Do not rewrite, soften, or extend
it based on other Argonne documents you may find — several are years out of date and
contradict it. Raise a proposed change with the coordinators instead.

## Conventions for `examples/`

- Every script takes the username from `ARGO_USER`, defaulting to `ac.jdoe`.
- Every Python file's docstring carries an `Install:` line before its `Run:` line.
- The username is not a secret, but it is an identifier: scripts note that it lands in
  shell history and should not go in `~/.bashrc` or a committed config.
- Shell examples are POSIX `sh`-compatible where they can be.

### `examples/open/` is the exception, deliberately

The open-weight models on `mango.cels.anl.gov` are not Argo, and `examples/open/`
departs from the rules above on purpose. Do not "fix" it to match its siblings:

- **`MANGO_HOST`, not `ARGO_USER`**, defaulting to `mango.cels.anl.gov`. There is no
  username in these calls at all.
- **`api_key="EMPTY"`.** The vLLM servers require the field and never read it. A
  participant's Argo username in that slot is wrong, not merely redundant.
- **Full served model names** — `RedHatAI/Llama-4-Scout-17B-16E-Instruct-FP8-dynamic`,
  not an Argo short ID and not the upstream `meta-llama/...` name either. The servers
  serve quantized builds; `GET /v1/models` on each port is the source of truth, the
  same way `GET /v1/models` is for Argo.
- Ports carry the meaning the way Argo uses model IDs: 8003 Llama chat, 8004 Qwen,
  9998 embeddings.

Measured on 2026-09-16 and worth keeping in the files: Qwen's internal reasoning
consumes `max_tokens`, so a small budget returns `content=''` with
`finish_reason='length'`; and only Qwen does tool calling — Llama on 8003 answers a
`tools` request with HTTP 400 asking for `--enable-auto-tool-choice` and
`--tool-call-parser`, which are server launch flags.

The prose copy of this material is `OpenModelCheatsheet.md` (contributed by the
coordinators), not a README section — so open-model changes touch four files, not
three: `README.md`, `argo-quickstart.html`, `OpenModelCheatsheet.md`, `examples/open/`.

## Housekeeping

- The network is **`Argonne-auth`**. Collaborators log in with their `ac.` username
  and the domain password they set up; Argonne staff use normal credentials. Keep the
  distinction the docs draw between that password (network only, never in a script)
  and the username (the entire Argo credential) — conflating them is the easy mistake.
- `Argo API Documentation.html` is Argonne-internal and gitignored. Keep it that way.
- Argonne links behind SSO or Box are not useful to external participants — most will
  not be able to open them. Point at the organizers instead.
